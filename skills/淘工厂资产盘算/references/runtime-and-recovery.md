# 运行、校验与中断恢复细则

正常执行以主 SKILL.md 固定流程为准；本页保留底层约束与恢复边界。

## 公司级安全续跑与校验

- 公司交付目录只保留业务 Excel（ERP 原始 Excel 位于「聚水潭订单」子目录）。公司运行记录、发布凭证、锁、模块工作文件和处罚表备份统一保存在导出目录之外：Windows 为 `%LOCALAPPDATA%/DeepSeekHarness/taogongchang-runtime/<输出路径摘要>/`，无 LOCALAPPDATA 时为 `~/.local/state/DeepSeekHarness/taogongchang-runtime/`。状态只含业务订单/本地路径/摘要，不含认证信息；不是可随意删除的垃圾文件。
- 内部 `.company-run.json` 记录公司、日期、模式、文件哈希和阶段；`.export-result.json` 为当前运行ID对应发布凭证，不能凭旧文件存在触发ERP。单公司持久OS锁禁止并发，不能靠删除锁文件解除正在执行的任务。旧版目录内状态不自动迁移、不自动重建任务，须核实完整状态或换新批次。为保证同盘原子替换，发布/回填时可短暂产生事务暂存文件，正常完成或可处理异常后清除；强制终止可能需要核实恢复，不能宣称从不产生临时文件。
- 续跑必须原公司、日期、模式、输出位置，使用同批次 `--resume`。导出完成后ERP失败不会重导账单；ERP任务按原状态恢复，不重复创建。回填中断只允许商品字段变化，其他文件哈希或输入目录清单变化会阻断。无新运行凭证的旧业务目录不自动迁移，请使用新批次；历史成果保持不动。
- 已完成主表或任一 ERP Excel 分片被人工改动时续跑阻断，不覆盖；ERP凭证核验全部分片哈希，不只核第一份。正常完成续跑只验证成果，不重复合并。零罚款/无订单不启动ERP；结构/精度异常停下而不是冒充空表。
- 回填前后校验非商品单元格、Sheet、行序、格式/金额不变。严格合并后校验固定30列表头、公司/总计、错误单元格及源处罚数据一致性；失败保留文件但不得报告全部完成。模板继承错误不计作合并新增错误。新全流程在严格合并后生成主表「待核查」页并调用安装的 LibreOffice Kit 重算，再检查公式保留、非公式数据不变及缓存无缺失/错误；引擎缺失、兼容失败或缓存错误时保留原合并文件并停止，不交付“重算成功”，不把公式换常量。
- `--erp-transport`、`--erp-browser`独立控制ERP会话；默认官方扩展，旧桥URL拒绝，淘工厂/ERP内存缓存隔离。两种日期区间均必填。
- ERP缺单属于明确的部分结果：报告missing_ids及匹配reason_counts，不声称全部订单匹配。新任务日志数量可为商品行数，不能等同订单数；候选多义仍阻断，最终订单集合精确核验。

### 自动重算与待核查页

- full 新运行（当前精简配置）：严格合并 → 一次结构/处罚来源校验 → 添加「待核查」「执行说明」页 → 重算到内部候选文件并验证缓存回填 → 哈希凭证先落盘 → 原子发布。不生成「金额对账」，不逐项金额审计，不重复全表验收。原处罚表不添加列/Sheet；公司目录仍仅业务Excel。
- 「执行说明」逐一显示17流程的成功、确认零数据、未执行/跳过/失败及凭证中实际记录的查询行数/查询条件。旧凭证无行数写“未记录”，不能凭文件数推断17份成功；零数据不等于导出失败。
- 本次罚款凭证为成功且有有效订单时，先执行聚水潭 `--prepare-only --fine-export-succeeded` 获取纯离线准备计划，再服务端检查现有会话。扩展连接失败与未登录分开报告；代理须按 recovery_action 在已打开浏览器自己的新Magpie标签页检查预填登录，登录后新scope获取Cookie，再原命令 `--resume`。Python不控制Magpie，不把输出指引当已执行；验证码由用户处理。无罚款/无有效订单不检查ERP、不创建任务。
- 执行成功与匹配完整度独立：`execution_status=completed` 不代表所有处罚已匹配；`matching_status`及待核查计数单独披露。准备失败保持当前公司/账单状态，不重导、不切换下一公司。
- 待核查依据本次 ERP matching.report，包含无订单、缺单、无效商品字段、多商品歧义的原Sheet/行号、文本订单号、原因、可唯一识别的处罚金额；金额列识别失败留空并提示，不能当零。无异常也明确显示无待核查记录。
- 优先使用显式 `TGC_RECALC_NODE/TGC_RECALC_CLI`，无覆盖时从已安装DeepSeek Harness的固定运行时/资源路径定位Node与LibreOffice Kit CLI（macOS应用包、用户运行时；Windows LOCALAPPDATA/ProgramFiles及可执行文件祖先）。显式覆盖无效立即报错，不静默换引擎；不递归全盘搜索、不寻找系统soffice、不安装替代引擎。自定义安装找不到时明确设置这两个环境变量。引擎计算子进程超时600秒（不含缓存回填及完整性检查耗时）；失败保留 merged 状态，原命令 --resume 从该阶段恢复，不重导、不重建ERP任务。旧 complete 交付不自动升级或覆盖。
- LibreOffice Kit 的原始输出可能改写等价公式或细微浮点序列化。实际交付只从真实计算结果按Sheet/坐标回填公式缓存；仅批准去可选Sheet引号、单格同端范围折叠等token级等价变化，其他公式变化阻断。原始公式、非公式单元格及未涉及ZIP成员保持，回填缓存逐项核对引擎结果，再执行严格验证；不是用自算常量替换公式。
- 当前精简配置不执行金额对账；相关历史审计代码/资料不属于默认主流程，不可据此报告金额审核通过。若用户另外要求财务审计，先确认范围和口径，不能自动插入本次恢复或交付。
- 发布前 journal 保存 merged_sha256、候选sha和 delivery_prepared，发布后中断可根据目标hash恢复；任何人工修改阻断。公式引擎可能改写Excel特有公式或产生错误，此时不绕过校验；真实兼容验证不等同业务金额核对。


### 中断恢复边界（不夸大保障）

- 若合并子进程已发布主表但 merged 摘要还未落盘即被终止，merge_running 续跑发现目标文件会阻断以免覆盖人工改动；须核实后恢复，不宣称这一窗口能自动重建。
- 若罚款已替换但ERP完成凭证尚未写入即进程被杀，会安全阻断；需核实外部备份并恢复原罚款后续跑，不能把不明商品改动当作ERP成功。完成凭证已经落盘的同窗中断可直接验证恢复。
- 下载内核按模块持久化远端任务：创建前写入creating意图，返回有效taskId后立即原子保存created；已知编号续跑只轮询/下载原任务。响应丢失或编号落盘失败时保守停止，不自动重建，也不猜最新下载记录。旧版未完成状态缺少此跟踪记录时同样停止，须人工核实。此保障不追溯修复旧历史任务，不保证任意中断点全自动恢复；正常导出完成后ERP失败仍不会重导账单。
- 创建前写入UTC `attemptStartedAt` 与模块/日期/查询行数摘要；新Hosting不确定任务恢复以该时间核验，不能依赖后续文件mtime。总编排先输出只读恢复计划，用户核实原编号并授权后才加 `--resume --recover-hosting-task-id <编号>`。仅旧状态显式加 `--recover-hosting-legacy-mtime` 才接受mtime证据。恢复与总编排持同一 `.company-run.lock`，Windows msvcrt单字节/macOS fcntl非阻塞锁；不得删除锁、以新锁路径绕过或通过环境变量伪造持锁。只允许export_running未发布阶段关联，备份/摘要/公司/唯一任务/日期/时间全部通过后原子写入，绝不因此重建任务或修改已完成批次。
- 原子替换支持一般进程异常恢复，不承诺断电/文件系统损坏事务。
- `--erp-expect-company` 仅在用户明确指定ERP公司时使用；共享ERP公司与淘工厂店铺可以不同，绝不自动套用淘工厂简称。
