# 金额对账：超长来源的无损拆分

## 行为与兼容

- `populate_audit(wb) -> dict`、`append_audit_sheet(source, destination) -> dict`、`audit_workbook(path, sources=None) -> dict`、`verify_audit(path) -> dict` 的调用签名不变。
- 来源仍按既有源 Sheet/自然行号排序，连续行号压缩成区间；重复来源不会去重。此处的“次序”指既有排序压缩后的规范次序，不声称保留原先按商品分组的遍历顺序。
- 短来源继续原样写入「金额对账」D列；短来源旧候选无需新增 Sheet，仍可核验。
- 超过 Excel 单元格 32767 UTF-16 单位的来源文本完整拆入新 Sheet「对账来源明细」。每片至多30000 UTF-16单位，不切断 Unicode 补充字符。拼接片段的 C 列即可还原原始规范来源文本（包括分号、重复项），不省略、不截断。
- 明细列固定为：审计页行号、分片序号、来源文本（按序无损拼接）。主审计 D列改为可核验的明细 C列范围引用、分片数及完整文本 UTF-8 SHA256；引用为静态文本，不新增公式或假缓存。

## 严格校验

`verify_audit` 从原始明细重新独立计算审计项及规范来源文本，再构造预期分片布局。主引用和明细表头、全部记录、所属审计行、片序、文字、顺序、重复次数逐单元格精确匹配；不只信任摘要或绿色状态。缺 Sheet、少片、多片、重排、错误归属、内容篡改、公式伪装文字、孤立额外来源 Sheet 均阻断。仍执行既有金额预期、实时引用、公式及真实重算缓存校验。

生成前拒绝已有「金额对账」或「对账来源明细」，不会覆盖。超长数据超过 Excel Sheet 总行数上限时仍失败关闭，绝不截断。所有布局计算在创建 Sheet 前完成。

## 不变边界

金额容差仍为绝对半分钱 `Decimal("0.005")`；独立金额口径、缓存来源/刷新流程、金额与状态公式均不变。不涉及 pipeline、ERP、导出或真实业务文件。`populate_audit`/副本 API 的结果仍只是待重算，不能当作交付成功。

## 离线回归

`tests/test_delivery_audit.py` 以临时目录合成工作簿覆盖：稀疏长来源（交错商品，无法连续压缩）、保存重载与全文重组、来源篡改九类、短来源与孤立表兼容、重复项和次序、32767边界、补充字符、Sheet行数限额。测试缓存注入仅为离线测试替身，不是经批准的重算引擎，也未执行真实业务文件重算。
