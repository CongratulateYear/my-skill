# 淘工厂资产盘算

## 1. 输入与依赖

- 用户提供：公司名称原文及顺序、支付起止日期、结算起止日期。两种区间均必填；单日填同一天。缺失先问，日期错误不自动纠正。
- 凭据仅在实际需要登录/换公司时使用；已有有效会话不再要密码。登录手机号、erpMobile不代替公司身份校验。只有用户明确指定时才加账号核对或ERP公司约束。
- 核验同一skills根目录的四个依赖：淘工厂登录、淘工厂导出、淘工厂合并、淘工厂聚水潭。基础脚本/模板缺失先补齐；执行对应环节前加载其skill。
- 使用已验证可用、具备openpyxl的Python绝对路径；不要假设Windows的python/py可用。公式引擎使用已安装的LibreOffice Kit，不另装、不找系统soffice。

## 2. 固定执行流程

只调用 `scripts/pansuan_pipeline.py` 编排，不在外部重复导出、ERP回填或合并。

1. **核对输入，固定批次目录。** 多公司开始前只生成一次 `--batch-folder`，每家公司及每次续跑原样复用。
2. **验证当前公司。** 脚本闸门有效则继续；公司未知/不符不导出。会话无法读取先检查浏览器与桥，不把 `no-session` 当作未登录。
3. **导出。** 默认17流程；按本次发布凭证区分有数据、确认零数据、失败。旧文件存在不代表本次完成。
4. **条件ERP。** 只有本次处罚成功且有有效订单号才执行聚水潭；确认零数据/合法空表无有效订单号则跳过。结构、公式或精度异常必须停下，不冒充空表。仅导出模式也执行适用ERP。
5. **严格合并一次。** full模式只使用本公司、本批次明细，ERP回填后由脚本 `--strict` 合并；不手工重合并、不用 `--accumulate`。仅导出模式不生成主表。
6. **必要校验与重算（用户2026-11-07选定精简流程）。** full模式保留「待核查」「执行说明」，合并后仅做一次结构/处罚来源一致性检查，再计算并回填缓存。缓存工具自身验收原数据、公式与缓存，不再重复openpyxl全表验收；哈希一致时发布后不再重扫同一主表。取消额外「金额对账」页及逐项财务对账，不生成、不执行，也不得报告为通过。600秒仅为引擎子进程超时。旧批次不自动改造；没有原结构验收凭证的历史续跑仍补一次必要检查。
7. **报告本公司结果。** 流水线完全退出并完成适用环节后才登录/执行下一家公司。流程完成但存在明确待核查可继续；执行失败必须先解决本公司。

### 登录恢复：只有一条路线

按淘工厂登录skill，在当前已打开浏览器里新建自己的Magpie标签；同一次恢复在自己的标签继续，不碰用户/其他代理标签，不新开浏览器或profile。

检查页面 → 已登录则接桥，未登录才检查表单并填缺失凭据 → 启动/复用正确桥 → 读取并直接evaluate随skill的 `bridge_agent.js` 完整源码 → 服务端公司校验通过 → 原流水线续跑。

- 桥未连接不等于未登录；代理返回started不等于验证成功。不把script标签插入当作连接凭证。
- **按顺序自动切换（用户固定偏好）**：用户已提供目标公司顺序及对应凭据时，服务端确认当前登录公司不是本轮目标公司，即在自己的Magpie标签真实退出并登录本轮目标公司，**不用再次询问**；包括开始执行时已登录其他公司的情况。多公司仍严格串行，上一家公司全部完成后才切换下一家，不跳过失败公司。公司未知时先核验，不能盲目退出；不得切换到用户清单外目标。该授权不涵盖ERP换号、验证码或合单范围批准。切换后仍须服务端公司验证，不反复注销、开页或提交密码。
- 淘工厂桥8899、ERP桥8901独立；ERP先复用会话，确实需要才用ERP凭据，绝不套用淘工厂密码/公司简称。
- 密码/cookie/XSRF/认证headers不落盘、不记日志、不回显；不得把含凭据的历史对话恢复到临时文件，事后删除也不允许。仅在内存上下文读取必要凭据；无法安全取得时请用户重供。验证码/短信/滑块由用户处理。

## 3. 命令与产物

以下为shell示例；PowerShell使用单行，替换为实际Python与skills路径。

```bash
python3 <skills-root>/淘工厂资产盘算/scripts/pansuan_pipeline.py \
  --company-name "公司A" \
  --order-pay-start 2026-09-01 --order-pay-end 2026-09-30 \
  --write-off-start 2026-09-01 --write-off-end 2026-10-31 \
  --batch-folder "<导出根>/批次_20261106_161000"
```

| 用户需求 | 附加参数 |
|---|---|
| 淘工厂资产盘算 | 默认full，全部17流程 |
| 淘工厂资产盘算导出 | `--mode export` |
| 淘工厂资产盘算导出罚款 | `--mode export --module 罚款` |
| 原任务续跑 | 原命令加 `--resume` |

默认导出根为Downloads/淘工厂导出。批次内公司明细目录与主表并列：

```text
批次目录/
  公司A_结算开始_结算结束/       # 原业务Excel；聚水潭订单位于子目录
  公司A_结算开始_结算结束.xlsx  # full主表
  公司B_结算开始_结算结束/
  公司B_结算开始_结算结束.xlsx
```

其他参数仅按实际需要使用：`--transport/--browser/--bridge-url` 控制淘工厂会话；`--erp-transport/--erp-browser/--erp-bridge-url` 独立控制ERP；`--erp-expect-company` 仅用于用户明确给出的ERP公司。`--output-dir` 覆盖主表位置，`--settlement-date` 覆盖主表日期标签；不要为续跑更改它们。`--fetch-file` 只用于用户明确提供的fetch输入，仍须校验公司并遵守登录skill的敏感输入清理规则。`--dry-run` 不登录、不导出、不触发ERP、不写文件。

## 4. 停止与恢复边界

| 情况 | 固定动作 |
|---|---|
| 验证码/短信、必要凭据缺失、合单范围待批准 | 等用户处理，保持当前公司与原任务 |
| 会话/浏览器桥问题 | 修复连接，原公司/日期/模式/输出位置加 `--resume` |
| 下载范围异常、损坏、外部修改、校验不通过 | 保留现场并停止；不绕过、不删除状态、不重新建不明任务 |

- **ERP连接恢复自动交接，不先问密码。** 只有处罚需要ERP且不能离线续跑时检查ERP会话。收到 `awaiting_agent` 后由当前agent立即按聚水潭skill恢复自己的Magpie标签、接桥并做服务端校验，通过后原命令 `--resume`。Python只给恢复指令，不控制浏览器、不保存凭据、不无限重试。`bridge_connection` 只表示连接问题，不能据此判定未登录；`session_inspection` 先检查页面，不猜过期/权限不足。实际缺凭据、验证码、权限不足才等待用户；一次恢复后仍同因失败则保留现场报告，不循环换号。
- ERP失败后不重导已完成账单；重算失败不重建ERP或手工重合并。完成后续跑只核验原成果，不自动升级旧主表。
- 合单固定授权（用户2026-11-07明确要求记录且不再询问）：有本任务真实查询合单证据的额外伙伴，允许仅保留于ERP原始导出，不新增处罚行或金额；此严格边界内不再重复提问。仍逐任务用聚水潭skill的 `scripts/jst_scope_approval.py` 离线生成绑定本任务、文件SHA-256、输出目录、请求顺序及额外集合的无BOM授权，再用原任务 `--resume --erp-scope-approval-file`；不手工拼JSON、不复用旧授权文件。未知格式或无证据额外订单仍阻断，不扩展到ERP换号、重新建单/下载或扩大处罚范围。
- 匹配字段固定：原始线上订单号→主订单编号，商品名称→商品标题，店铺款式编码→商品id。只覆盖明确匹配的商品字段；无订单/缺单/商品缺值/多义保留原值并列待核查，原11列、Sheet、行序、金额、格式不变。
- 原始ERP导出独立保存；备份/日志/凭证在内部runtime，不能进入合并输入；不删除锁或状态解锁。
- 保留公司身份、ERP订单范围与明确匹配、处罚非商品字段不变、文件哈希及事务发布、一次结构/处罚来源检查、公式缓存工具的正确性验收。取消额外金额对账及重复全表检查，不削弱回填字段和订单对应检查。必要检查失败仍不发布。
- 不承诺任意中断点自动无重复：远端建任务后状态未记录、合并发布但摘要未落盘、罚款回填但凭证未落盘等窗口，先核实再恢复。

## 5. 进度与交付口径

后台任务启动后保留job id，优先等待宿主完成通知；只有诊断需要或确实被该结果阻塞时才读取，不连续重复查询相同状态。一次等待超时后若无新事件，不立即用相同参数再等；没有独立工作时结束当前回复，等待完成通知继续。阶段切换及 `stage_completed` 记录在脚本事件流，但对用户合并报告有意义的阶段变化、异常和最终结果，不逐条转述内部子阶段或60秒心跳。无新事件的自动续轮直接结束，不向用户重复发送“等待中”；同一阶段、同一异常、同一等待用户事项只通知一次，直到阶段变化或收到新输入。此约束是agent通知策略，不是新增宿主调度器。默认心跳60秒仅供故障诊断；完成阶段的 `stage_elapsed_seconds` 用于性能分析，不伪造百分比或预计完成时间。长步骤不因耗时长重跑。脚本进度不是成功凭证；退出码与最终校验结果共同判定。

ERP失败时优先读取本次流水线输出的 `recovery`：`evidence_file/state_file` 是本公司本调用直接计算的路径，不遍历历史runtime猜文件。只有任务/请求顺序/输出/待验收绑定初筛一致才提供 `approval_argv`，这不是批准或完整验收；执行前核对既有用户授权边界，生成器仍须重新校验文件哈希、合单证据和完整六字段。`approval_file_exists=true` 时不得覆盖/删除，先按原任务核实已有授权。不要自动执行未验证范围、重建下载或更换ERP账号。

当前状态只以本次流水线最终JSON的 `summary` 为准，不再手工维护第二份阶段状态；历史过程与当前结论分开。顶层 `execution_status` 表示流程，`summary.matching_status` 表示匹配，三项校验分别报告。ERP子结果 `ok=false/complete=false` 不单独解释为整个流程失败；未知历史匹配状态不解释为匹配完整。`review_guidance` 给出核查方向，不自动扩大查询或猜填。`summary.review_focus` 集中列出待核查行数、原因计数、金额已知/未知行数、去重缺单数及核查页位置；历史缺失值保持null，不把缺单行数当唯一订单数，也不将未知金额视为零。

缺凭据、验证码或范围授权时只询问一次，在当前会话任务记录中标明“等待用户输入”、缺失项及原公司/批次/job id（不记录秘密）；结束当前回复等待用户。无新输入或新会话证据，不重复催问、重启或把自动续轮当作用户授权。收到输入后从原停止点核验并续跑；等待用户不记作执行失败，不为等待另建框架或改写业务状态。

每家公司报告一行，全部结束给总表：公司/日期、主表路径（仅导出无主表）、原始目录、流程有数据/零数据/失败数量、处罚总行数/匹配/原因计数、ERP缺单、待核查行数/金额/金额未知数、重算/结构结果及金额对账是否执行（精简流程明确写未执行，不写通过）。缺失的历史统计写“未记录”，不猜17项成功、不把无法识别金额记为零。

对用户只用三种结论：**流程完成，匹配完整**；**流程完成，存在待核查**；**流程未完成，需要处理后续跑**。ERP跳过明确写原因。执行完成不代表全匹配；缺单行数不等于缺失唯一订单数。金额对账不替代财务审计。

## 2026-11-07 第二轮编排优化

- 通知优先适用于自动续轮：在会话任务上下文保留唯一后台job id及是否已读。`scripts/orchestration_policy.py:wait_decision` 是纯决策约束，不是宿主调度器；自动续轮、心跳或无新事件都不算新读取理由。已有一次运行中结果后，必须等宿主完成/失败通知，或有明确诊断原因，才再次收集；不得以“继续目标”重复等待。无需为此改业务journal，也不保证宿主一定发送通知。
- 通过公司闸门、即将导出时仅对现有本机ERP桥做一次有界 `/ping` 诊断（cookie-only不探测）。不读cookie、不查询ERP订单、不启动8901、不打开ERP页；结果仅连通状态，登录态始终unverified。未连接只提示，不阻断账单；实际ERP准备/恢复仍严格以本次有效罚款订单为条件。自定义非本机桥不提前探测，后续原会话约束不变。
- 已记录有证据合单伙伴仅ERP保留的固定授权时，运行命令显式加 `--erp-proven-partner-consent`（无授权不加；不得从错误结果推导同意）。ERP子进程退出并释放任务锁后，若本调用精确证据初筛符合、没有显式授权文件且新目标不存在，编排调用原 `jst_scope_approval.py` 完整离线重验六字段/SHA/合单证据，再保持原输入加resume及新授权，最多续跑一次。生成拒绝或续跑失败立即停止，不循环、不重新下载/建单、不删除状态。已有授权目标不覆盖或自动复用，返回恢复计划人工核实。此开关不是下载异常、无证据范围扩大或ERP换号的批准。授权文件仍由既有生成器产生，不手拼。
- 本优化不自动重跑历史已完成公司，不改旧账单、已交付主表或旧任务状态。

## 2026-11-07 最小补强边界

- 保持原主流程和两条对外状态（执行、匹配），不增加审批链或第二套业务状态源。
- 在创建journal或业务任务前一次预检目录写入、依赖与模板；失败明确停止，不改ACL或系统设置。dry-run仍无写入、无网络。预检不能保证后续磁盘/权限永不变化。
- 任务编号在入口规范为有效字符串；拒绝bool、空值和非法编号。恢复提示不是授权，ERP生成器仍核验原始六字段、文件摘要及合单证据。
- 淘工厂与ERP各一有效桥；导航或换号重新验证，代理冲突不靠反复开页解决。协议更新只在业务空闲时重启自己管理的服务并重新注入，不热替换运行中任务。
- 导出恢复以模块持久任务记录为准，已知编号优先接回；没有编号、创建结果不确定、旧未完成记录不足时保留现场停止，不自动重建、不猜最新任务。不手改状态模拟成功。
- 本轮仅离线测试；不修改已交付主表、账单、历史业务journal，不以真实订单验收代码。
