# 淘工厂资产盘算

## 依赖（本 skill + 四个配套 skill）

本 skill 依赖以下三个基础 skill 及一个条件 skill。**下载/安装时应检查并配齐四个依赖到同一 skills 目录**，核验实际安装文件，不仅凭文档声称安装成功：

| 依赖 | 位置 | 作用 |
|---|---|---|
| 淘工厂登录 | `<skills-root>/淘工厂登录/` | magpie-browser 登录/切换公司；`ensure_login.py` 登录闸门（cookie 库读不到时自动回退浏览器桥）；cookie 库解密 |
| 淘工厂导出 | `<skills-root>/淘工厂导出/` | `taogongchang_export.py` 17 个账单流程导出到单一文件夹（下载器已内置） |
| 淘工厂合并 | `<skills-root>/淘工厂合并/` | `merge_excel.py` 合并成盘算式工作簿（公司汇总 30 列 + 流程 Sheet；构建器与模板已内置） |
| 淘工厂聚水潭 | `<skills-root>/淘工厂聚水潭/`（`taogongchang-jushuitan`） | 条件依赖：本次罚款数据成功导出后，查ERP订单并回填商品标题/商品id，直接回填原处罚数据，ERP原始导出保存到独立子目录 |

流水线脚本自检前三个基础依赖，在本次罚款发布凭证核实成功且存在有效订单号时调用聚水潭条件依赖。缺失时停止补装，不绕过。**现已自动串联：登录 → 导出 → 条件ERP回填 → 一次严格合并 → 内置校验。代理不再额外手动重合并。**

## 罚款导出后条件调用聚水潭

- **只有本次实际执行且成功完成罚款/处罚数据导出，才执行「淘工厂聚水潭」skill。** 全部17流程包含罚款，成功导出后也适用；单独导出罚款同样适用。仅导其他流程、手动或持久化跳过罚款、罚款失败/未完成、只做本地合并、dry-run，均不得调用。不能因为目录存在旧文件或参数为all就当作本次已成功导出。
- 从本次导出结果/运行状态核实处罚数据模块成功，并准确定位本公司、本日期、本次发布的罚款Excel。续跑只接受同一批次、公司、日期已核实的完成结果；不得拿别的批次或公司的旧表凑数。
- 已确认零数据或合法空表没有有效主订单号时，报告“罚款导出成功但无可查询订单，跳过聚水潭”，不启动ERP登录/查询。数值精度失真、公式或结构异常不是空数据，必须停止报告，不猜订单号。
- 有有效主订单号时，加载 `taogongchang-jushuitan`，传入本次罚款路径 `--fine-file`、用户公司原文 `--shop-name` 和明确的 `--trigger fine-export`。普通订单导出不得隐式匹配。ERP优先复用已登录会话，失效才询问ERP凭据，不能复用淘工厂密码或会话；不要自动把淘工厂公司简称当ERP公司约束。
- 映射：ERP“原始线上订单号”→罚款“主订单编号”；“商品名称”→“商品标题”；“店铺款式编码”→“商品id”。直接回填原处罚数据；商品id和商品标题以聚水潭为准，明确匹配时覆盖原值。多商品歧义、未匹配或ERP缺值保留原值并报告。保持原11列/Sheet/行序/金额/格式；备份放合并输入目录之外，ERP原始导出放“聚水潭订单”子目录，不添加匹配副本或报告Sheet。
- 基础流水线成功后完成适用的ERP步骤，再报告整家公司完成。ERP失败时保留账单成果并明确“账单完成，ERP匹配未完成”，不得报全部成功；处理完本家公司后才切下一家公司。已有ERP任务/下载使用--resume核实，不重复建任务。
- 本步骤同样适用于export模式：不合并不代表不做罚款后的ERP匹配。回填后的处罚数据仍是合并器唯一处罚输入；ERP子目录和外部备份不进入合并。full模式由脚本在ERP回填完成后用原明细目录严格合并一次（覆盖式重建，绝不用--accumulate），再校验交付主表。

**任务安全：** 使用聚水潭真实ExportBySync→日志auto_id流程及持久化状态续跑；关联不明确不重建任务。部分订单缺失时明确报告部分成功，不称全部匹配完成；下载订单集合必须核验。

## 输入（全部来自用户消息，缺了先问，不要自行编造）

每家公司需要：
1. **公司名称**：用户消息原文（如「埔鸣」）——用于登录公司校验、导出/合并文件命名。
2. **支付日期 + 结算日期**：`YYYY-MM-DD` 单日或区间（导出的查询条件；结算区间同时是文件夹/文件名后缀）。
3. **账号/密码**：仅当浏览器登录态失效或需要换公司时才用；按「淘工厂登录」skill 的红线执行——**密码绝不落盘、绝不回显**。登录手机号只用于填表，不自动作为身份约束；多个手机号可登录同一公司。
4. 可选：用户贴的 queryBillDetail fetch 文本（`--fetch-file`，提供后跳过本机浏览器登录闸门，但导出内核仍用该 fetch 的会话验证目标公司；公司未知或不符必须停止）。

## 执行

### 单公司

1. 需要时先按「淘工厂登录」skill 登录/切换到目标公司（当前已打开的浏览器、新开 Magpie 标签页；wrong-company 时右上角公司名 → 退出登录再登目标账号）。
2. 跑流水线（登录闸门在脚本里自动执行；未登录/公司不符/两路登录态都拿不到会以 exit 3 停下，并把 `ensure_login.py` 的 `reason` 和 `action` 指引原样转出——cookie 库被锁或 v20 加密时按指引起浏览器桥：后台跑 `淘工厂登录/scripts/browser_bridge.py --port 8899`，再对已登录 tgc 标签页注入 `http://127.0.0.1:8899/agent.js`）：

```bash
# 淘工厂资产盘算（全流程）
python3 <skills-root>/淘工厂资产盘算/scripts/pansuan_pipeline.py \
  --company-name 埔鸣 \
  --order-pay-start 2026-09-01 --order-pay-end 2026-09-30 \
  --write-off-start 2026-09-01 --write-off-end 2026-10-31

# 淘工厂资产盘算导出（不合并）
... --mode export

# 淘工厂资产盘算导出罚款（只导处罚数据）
... --mode export --module 罚款

# 用户贴了 fetch 文件（无需登录态）
... --fetch-file /path/to/fetch.txt
```

3. 脚本自动完成适用的聚水潭回填及一次严格合并。ERP登录失败时保留账单并返回需干预，完成ERP登录后原命令加 --resume，**不得重导账单或手工重复建ERP任务**。

4. 交付：两个基础产物并列：`<导出根>/<公司名称>_<结算开始>_<结算结束>/` 保留原始导出 xlsx、运行状态和下载工作目录；`<导出根>/<公司名称>_<结算开始>_<结算结束>.xlsx` 为合并主表。默认导出根为用户 Downloads/淘工厂导出；显式 `--settlement-date` 只覆盖主表日期标签。仅导出模式目录不变，不生成主表；不移动此前真实结果。

跨平台：`<skills-root>` 用实际技能安装路径替换，支持中文/英文技能目录；macOS 用 python3，Windows 用 py -3 或带依赖的 Python。上方换行示例为 shell 格式，PowerShell 请用单行命令。

### 多公司（严格串行）

开始第一家公司前，先确定一次性的批次总目录，例如 `<导出根>/批次_20261105_111600/`。
本批次每家命令**必须复用同一个** `--batch-folder "<批次总目录>"`；导出会自动创建总目录及其公司子目录。
续跑也用原批次目录，不能每家公司或每次续跑重新生成时间戳。每家公司原始导出目录和合并主表直接并列放在此批次总目录，不再套公司包装目录。

```text
淘工厂导出/
  批次_20261105_111600/
    公司A_2026-09-01_2026-10-31/
      商品贷款.xlsx
      …其他流程明细及运行状态
    公司A_2026-09-01_2026-10-31.xlsx
    公司B_2026-09-01_2026-10-31/
      …原始导出明细及运行状态
    公司B_2026-09-01_2026-10-31.xlsx
```

身份判据：默认始终用 `--company-name` 传给登录闸门的 `--expect-company` 校验公司，不自动把用户登录手机号传成 `--expect-account`。公司匹配时 `erpMobile` 不同不阻断；公司不符或未知必须停下。只有用户明确要求核对特定账号时才传 `--expect-account <指定账号>`（默认仅诊断），明确要求严格核对再加 `--strict-account`（须同时有账号，可比不符即阻断，未知仍未核实）。

参数：`--resume` 续跑；`--browser`、`--transport`、`--bridge-url` 同时透传登录/导出；`--output-dir` 仅显式覆盖主表位置，优先级最高；省略时主表与原始导出目录并列（导出根或批次总目录）；`--dry-run` 只打印命令，不登录、不触发导出、不写文件。


- 按用户列出的顺序，**一家一家来**：公司A（登录切换 → 导出 → 条件聚水潭 → 一次严格合并与校验 → 确认交付）→ 才开始公司B（退出A、登录B → 流水线）→ 依此类推。
- **必须等上一家流水线完全退出（含合并及适用的聚水潭步骤处理完毕）才能开始下一家的登录切换**；禁止并行、禁止交叉跑多家公司。
- 每家换公司前都要走「淘工厂登录」的退出/登录流程（同一浏览器，新开 Magpie 标签页，不新开浏览器）。
- 某家中途失败：先修复该公司（导出加 `--resume` 续跑；合并幂等重建），完成后再继续后面的公司，顺序不变。
- 每家完成后向用户报告一行结果（导出行数/合并文件路径），全部完成后给总表。

## 注意（红线）

- **浏览器**：不要新开浏览器；只在当前已打开的浏览器里操作；每次操作新开 Magpie 标签页，不复用已有标签页；不绕过验证码（滑块/短信让用户手动过）。
- **敏感信息**：cookie、密码、XSRF/headers 绝不落盘、不写日志、不回显到聊天。
- 启动时在登录/建目录前校验已提供日期的真实日历值、成对参数和区间顺序；日期错误不自动纠正。全流程合并强制 `--strict`，账单无法识别或读取失败不得交付成功主表。
- 合并的结算日期缺省取结算区间（write-off），没有再退支付区间，再退当天。
- export 模式跑完后用户想合并：直接跑「淘工厂合并」skill，无需重导。
- 运行脚本用 `python3` 即可；依赖脚本各自负责找带 openpyxl 的 Python。

身份字段说明：`erpMobile` 仅为 ERP 绑定信息，不代表当前实际登录手机号；公司名称才是默认身份判据。

## 公司级安全续跑与校验

- 公司目录内 `.company-run.json` 记录公司、日期、模式、发布文件哈希和阶段；`.export-result.json` 为当前运行ID对应发布凭证，不能凭旧文件存在触发ERP。仅包含业务订单/本地路径/摘要，不含认证信息。单公司OS锁禁止并发。
- 续跑必须原公司、日期、模式、输出位置，使用同批次 `--resume`。导出完成后ERP失败不会重导账单；ERP任务按原状态恢复，不重复创建。回填中断只允许商品字段变化，其他文件哈希或输入目录清单变化会阻断。无新运行凭证的旧业务目录不自动迁移，请使用新批次；历史成果保持不动。
- 已完成主表被人工改动时续跑阻断，不覆盖；正常完成续跑只验证成果，不重复合并。零罚款/无订单不启动ERP；结构/精度异常停下而不是冒充空表。
- 回填前后校验非商品单元格、Sheet、行序、格式/金额不变。严格合并后校验固定30列表头、公司/总计、错误单元格及源处罚数据一致性；失败保留文件但不得报告全部完成。模板继承错误不计作新增；公式缓存仍需Excel/WPS打开重算。
- `--erp-transport`、`--erp-browser`、`--erp-bridge-url` 独立控制ERP会话；ERP桥8901和淘工厂8899绝不混用。两种日期区间均必填。
- ERP缺单属于明确的部分结果：报告missing_ids及匹配reason_counts，不声称全部订单匹配。新任务日志数量可为商品行数，不能等同订单数；候选多义仍阻断，最终订单集合精确核验。

### 中断恢复边界（不夸大保障）

- 若罚款已替换但ERP完成凭证尚未写入即进程被杀，会安全阻断；需核实外部备份并恢复原罚款后续跑，不能把不明商品改动当作ERP成功。完成凭证已经落盘的同窗中断可直接验证恢复。
- 本公司级日志不替代下载内核逐模块任务日志：淘工厂模块在远端任务创建后、模块完成状态前中断，原内核仍可能重建该未完成模块任务。遇此类异常先核实远端任务，不承诺任意中断点全自动无重复。正常导出完成后ERP失败的续跑不会重导账单。
- 原子替换支持一般进程异常恢复，不承诺断电/文件系统损坏事务。
- `--erp-expect-company` 仅在用户明确指定ERP公司时使用；共享ERP公司与淘工厂店铺可以不同，绝不自动套用淘工厂简称。
