# 淘工厂资产盘算

## 1. 职责与唯一规则来源

本skill负责输入绑定、串行调度、恢复交接和交付口径，不重复实现子流程：

| 组件 | 唯一职责与执行前必须加载的skill |
|---|---|
| 总流程 | 本skill；单公司固定 `scripts/pansuan_pipeline.py`，不能在外部重导、回填或手工合并 |
| 会话 | `taogongchang-login`：浏览器/profile配置、真实表单恢复、公司服务端验证、内存Cookie和连接页归属清理 |
| 导出 | `taogongchang-export`：17类任务、持久任务身份、Hosting快照关联、下载与安全解压 |
| ERP | `taogongchang-jushuitan`：有效处罚订单条件查询、范围授权、字段匹配与原始导出 |
| 工作簿 | `taogongchang-merge`：固定30列表头、模板结构和严格合并；重算用已安装LibreOffice Kit |

公共Playwright适配器以淘工厂登录skill的实现为准，导出skill仅保留兼容入口，禁止复制另一份逻辑。各skill的历史优化记录不是额外授权；同一约束不因重复记载而扩大。

## 2. 输入与安全边界

- 公司名称原文及顺序、支付起止日期、结算起止日期均由用户提供。单日同起止；缺失先问，不猜日期。多公司只生成一次批次目录，所有续跑保持同一批次、顺序、日期、模式和输出位置。
- 使用已验证具备openpyxl/lxml的Python绝对路径；子进程复用 `sys.executable`。核验同一skills根目录四个依赖和模板。公式引擎只用已安装LibreOffice Kit，不装替代引擎、不全盘搜索或假定系统soffice可用。非标准布局可显式配置 `TGC_RECALC_NODE` / `TGC_RECALC_CLI`，无效即停止。
- 浏览器与扩展配置按登录skill唯一规则：同profile的Magpie与官方Playwright扩展；只连接当前浏览器。连接失败不等于业务未登录。
- 密码、Cookie、XSRF、认证headers、扩展令牌只在表单/执行期内存使用，不写命令参数、批次清单、普通日志、状态或回复；不得将含凭据的历史对话恢复到文件。公司身份不能由手机号、页面公司名或Cookie取得替代。
- 用户已提供公司顺序及对应凭据且服务端确认公司不符，允许在本次恢复新建的自己Magpie页真实退出并登录目标公司，无须重复询问。未知身份先核验；不碰用户/其他agent标签，不新开浏览器/profile。此授权不涵盖ERP换号、验证码或合单范围扩大。
- ERP已登录复用，不比较/切换账号，不套用淘工厂密码或公司名。仅用户明确指定时传ERP公司约束。

## 3. 固定业务流程

1. **预检并绑定输入。** 创建业务journal/任务前检查依赖、模板、目录写入；失败不改ACL。dry-run无写入、无网络。
2. **服务端验证本公司。** 错公司不导出；未知公司不盲目退出，按登录skill核验。每公司独立SessionScope，淘工厂/ERP隔离且ERP懒获取；换号后新scope，不热替换运行中会话。
3. **导出17流程。** 只以本次发布凭证区分有数据、确认零数据、失败；旧文件存在不代表完成。
4. **条件ERP。** 仅本次处罚成功且有有效订单号时执行；零数据或合法空表无有效订单时跳过。结构/公式/精度异常必须停，不能冒充空表。仅导出模式也执行适用ERP。
5. **严格合并一次。** full模式在ERP回填后仅合并本公司、本批次源；不手工重合并、不用accumulate。export模式无主表。
6. **精简校验与重算。** 保留「待核查」「执行说明」；一次结构/处罚来源一致性检查，再用Kit计算并移植缓存。缓存工具验收原数据、公式及缓存；哈希一致的发布文件不再次全表扫描。无原结构验收凭证的历史续跑补一次必要检查。600秒是引擎子进程超时，不是无限等待或重试许可。
7. **交付后才下一家公司。** 前一家子进程退出且适用环节完整完成后才进入下一家；有明确业务待核查可继续，未完成公司不跳过。

不生成、不执行额外金额对账或财务审计，不报告为通过。未知ERP商品不猜填；不得为得到全匹配放宽规则。

## 4. 单公司入口与产物

```bash
python3 <skills-root>/淘工厂资产盘算/scripts/pansuan_pipeline.py \
  --company-name "公司A" \
  --order-pay-start 2026-09-01 --order-pay-end 2026-09-30 \
  --write-off-start 2026-09-01 --write-off-end 2026-10-31 \
  --batch-folder "<导出根>/批次_20261110_100000"
```

| 需求 | 参数 |
|---|---|
| 完整盘算 | 默认full、全部17流程 |
| 仅导出 | `--mode export` |
| 仅导出处罚 | `--mode export --module 罚款` |
| 原任务续跑 | 原命令加 `--resume` |
| 多公司统一入口 | 用 `--companies "公司A" "公司B"` 替代 `--company-name`，其余日期与批次参数相同；两者互斥 |
| 已授权核实Hosting编号 | `--resume --recover-hosting-task-id <编号>`；旧状态仅显式允许时加 `--recover-hosting-legacy-mtime` |

### 固定输出位置与格式（跨平台硬约束）

- 无论macOS还是Windows，默认输出根目录必须是**当前用户系统「下载」目录下的 `淘工厂导出`**；Windows应解析系统Downloads（包括重定向位置），不得硬编码用户名、盘符。不得因为当前工作目录不同就输出到项目目录、Documents、桌面或skills目录。仅用户明确指定其他位置时允许覆盖。
- 多公司同一次任务只建立一个 `批次_YYYYMMDD_HHMMSS` 目录，按用户顺序串行交付；续跑复用同一批次，不另建批次、不移动已有运行状态。
- 每家公司主表固定为 `公司名称_结算开始_结算结束.xlsx`，与同名源目录**直接并列于批次根目录**。不增加「汇总输出」层、不增加公司包装目录、不把各公司明细平铺混放。
- 源目录中的账单明细沿用导出skill固定流程名称，例如 `消费者体验提升服务.xlsx`、`商品贷款.xlsx`、`交易佣金.xlsx`、`处罚数据.xlsx`、`所有商品效果数据导出.xlsx`；**不加店铺前缀，不把 `商品贷款.xlsx` 改成 `商品货款.xlsx`**（后者仅为工作簿Sheet名称）。其余明细名称同样由导出skill定义，不另造命名规则。确认零数据的流程不伪造明细文件；不得仅凭缺少文件认定零数据。
- 条件ERP原始导出单独放在公司源目录的 `聚水潭订单/` 子目录；仅实际执行并成功导出时存在。内部备份、日志、状态、凭证不得进入合并输入，不当作业务交付明细。

```text
系统下载目录/淘工厂导出/批次_YYYYMMDD_HHMMSS/
├── 公司A_结算开始_结算结束.xlsx
├── 公司A_结算开始_结算结束/
│   ├── 消费者体验提升服务.xlsx
│   ├── 商品贷款.xlsx
│   ├── 处罚数据.xlsx
│   ├── 所有商品效果数据导出.xlsx
│   └── 聚水潭订单/             # 仅条件ERP实际产出
├── 公司B_结算开始_结算结束.xlsx
└── 公司B_结算开始_结算结束/
```

- **禁止旧版入口回退**：资产盘算只走本skill的 `scripts/pansuan_pipeline.py`，不得恢复、安装或调用已删除的旧版 `asset-inventory`、`multi_shop_runner.py` 代替总流程。子skill内部自带构建器是正常依赖，不属于被删除的独立旧版入口。
- 新版主表必须经过本skill规定的条件ERP、严格合并、结构验收与Kit公式缓存重算，保留「待核查」「执行说明」。不得把旧主表复制、改名或搬到下载目录就宣称新版完成；未完成环节必须如实报告。
- 最终交付前核对实际路径、目录层级、文件命名与完成凭证；链接使用实际完整路径，不使用相对于错误工作目录的短链接。历史正式文件不自动搬动、覆盖或删除。

仅按实际需要传transport/browser；ERP独立erp-transport/erp-browser。旧bridge仅playwright别名，非空bridge-url拒绝。output-dir和settlement-date不能在续跑改变。fetch-file仅用于用户明确提供的fetch并按登录skill处理敏感输入。

## 5. 恢复协议：交接不等于失败

- **agent可恢复（awaiting_agent）**：本公司会话失效、公司不符或需要检查扩展/ERP页面。立即按相应登录skill在自己新建页判断并恢复；新scope服务端校验，原批次续跑。Python只输出恢复交接，不读取凭据、不直接控制Magpie，也不自动提交验证码。
- **用户待处理（awaiting_user）**：实际缺少凭据、验证码/短信/滑块、权限不足、ERP额外范围待批准。只问一次，记录非敏感缺失项及公司/批次/job id；无新输入或新证据不得重复催问、重启。等待不记业务失败。
- **真实失败（failed）**：损坏、外部修改、范围异常、结构或公式验收失败、身份绑定冲突。保留现场并停止，不删锁/状态，不绕过校验。
- **完成且有待核查**：执行完成；匹配状态另报，不当作失败或盲目重试理由。

一次恢复后仍同因失败须停下诊断，不循环换号或重填密码。ERP恢复不重导已完成账单；重算恢复不重建ERP或手工重合并；完成后续跑只核验已有成果，不升级旧主表。

### 不确定任务与ERP边界

- Hosting已知编号接回原任务；新状态具有创建前完整快照且允许回执兜底时，下载内核在公司锁内校验新增编号、精确任务名、请求摘要、原UTC时间窗及完整列表唯一性后关联。禁止取最新任务。旧无快照、创建网络结果未知、有效编号冲突或证据不足仍需显式核实恢复，不能重建。
- 显式恢复与流水线共用OS公司锁，持锁复核状态SHA/公司/日期/唯一任务及FINISHED，备份后原子关联。已完成/已发布批次不适用。
- ERP额外合单范围仅用户本任务明确批准，或当前用户可核实适用的持续授权。无授权不加 `--erp-proven-partner-consent`。仅真实查询合单证据支持的伙伴可保留于ERP原始导出，不新增处罚行/金额。按聚水潭skill生成器离线复核六字段、SHA与证据后原任务续跑；不手拼授权JSON、不复用旧授权、不覆盖已有目标、不扩大无证据范围。
- 恢复输出的evidence_file/state_file只取本调用绑定路径，不遍历历史runtime猜文件。approval_argv只是计划，不是授权。现有授权文件先核实，不自动删除。
- 匹配固定：原始线上订单号→主订单编号，商品名称→商品标题，店铺款式编码→商品id。只覆盖明确匹配商品字段；原11列、Sheet、行序、金额、格式不变。无订单、缺单、多义、空商品保留原值列待核查。
- 远端已创建但本地未记、发布未记摘要、回填未记凭证等窗口不承诺自动无重复；先核实，不能删除现场模拟成功。

## 6. 脱敏证据与离线验收

诊断仅记录有界枚举/类型/计数和必要任务身份摘要：Hosting在状态中记录 `hostingAssociation=direct_id|verified_snapshot` 和有界 `hostingResponseShape`；登录适配器 `cleanup_evidence()` 返回本进程最近32条清理事件副本，状态为 `closed/not-owned/disconnected/failed`。INFO日志仅按调用方配置启用，不强制改变全局日志；进程结束后不得声称仍保留内存证据。不得输出原始响应、Cookie、完整URL/认证参数。清理只关可证明属于当前实例的官方连接页；旧页和业务页不清扫，清理断连不能覆盖已取得Cookie，disconnected不证明页面已关闭。

回归覆盖串行换号交接、导出后ERP过期续跑、Hosting无ID回执及恢复、不确定任务拒绝、连接页关闭断流、身份冲突及用户等待。默认离线mock，不创建真实任务，不修改已交付批次；通过离线测试不等于全部真实平台场景已验收。

## 7. 进度与最终交付

保留后台job id，优先宿主完成通知；已读运行中状态后，无新事件/明确诊断原因不反复读取或等待。无独立工作则结束当前回复。自动续轮、心跳不是新授权或读取理由。阶段变化/异常/最终结果合并通知，同等待事项只说一次，不伪造百分比或预计耗时。`scripts/orchestration_policy.py:wait_decision`只是纯决策，不是宿主调度器。

单公司最终JSON `summary`及业务journal是权威，批次调度只维护输入/顺序及结果引用，不复制另一套业务阶段。执行和匹配两轴分开；ERP子结果ok=false不能单独推断总失败；未知统计写未记录/null，不猜零或17项完成。

每公司最终报告：公司/日期、主表与源目录、有数据/零数据/失败数量、处罚总行数/匹配/原因、去重ERP缺单数、待核查行数/金额及未知金额数、结构/重算结果、金额对账未执行。待核查使用summary.review_focus与review_guidance，不自动扩范围。对外结论只用：**流程完成，匹配完整**；**流程完成，存在待核查**；**流程未完成，需要处理后续跑**。等待恢复同时说明awaiting_agent/awaiting_user，不混称程序失败。
