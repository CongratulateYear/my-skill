# 月度货款对账

把钉钉审批的供应商货款与售后登记的后台退货、仓库退货、罚款、拦截逐条匹配，生成一张可核对、可溯源的月度对账表。

## 输入与输出

**两个必填输入**（向用户要文件路径，缺一不可）：

1. **钉钉审批表**：含「费用类型/结算时间/运营/产品名称/店铺/对接群/收款账户/报销金额/审批结果/货款所属月份」列的总表 sheet
2. **退货登记表**：扣款侧数据，两种格式都能自动识别——
   - 汇总格式：sheet 名含「汇总」（拦截-罚款-退货 汇总），收款人列
   - 售后台账格式：含「厂家」「财务」列（厂家=收款方，财务列可反推运营归属）

**必问三要素**（缺任何一个都先问，禁止默认或沿用历史会话里的文件）：
1. **对账月份与年份**：如 8月、2026（年份未说可默认 2026，但月份必须用户明确说出）
2. **钉钉审批表路径**：用户本次给的文件路径；不得自行使用上次会话或桌面上的旧同名文件
3. **退货登记表路径**：同上

运行前向用户复述一遍「月份 + 两个文件名」确认无误再跑（同名多版本文件曾导致对账结果两次不一致）。

**输出**：`{月份}对账表_{年份}.xlsx`，8 个页签：主表（{月份}对账表）、核对总览、匹配明细、未匹配清单、大额无售后、破零自刷款、运营-财务映射、口径说明。最终效果见 `assets/示例_8月对账表_2026.xlsx`。

## 执行步骤

1. 向用户确认三要素：钉钉审批表路径、退货登记表路径、对账月份+年份，并复述文件名核对。文件不存在或列缺失时向用户报告，不要猜。
2. 准备 Python 环境：优先用含 openpyxl 的解释器（本机可用 `/Users/rabbit/.workbuddy/binaries/python/envs/default/bin/python3`）；没有则 `python3 -m pip install openpyxl` 后再用。
3. 运行：

```bash
python3 scripts/build_duizhang.py \
  --dingding <钉钉审批表.xlsx> \
  --deduct <退货登记表.xlsx> \
  --month 8月 --year 2026 \
  [--out 输出.xlsx] [--threshold 10000]
```

4. **看预检结果**：脚本运行先输出「预检」段（两侧各 sheet 的目标月行数/金额/占比、0 元噪声计数、聚合格式检测）。出现 ⚠ 警告（目标月占比异常低、扣款仅占货款 <3%、检测到聚合格式 sheet 等）时先把 ⚠ 原文报给用户、确认口径（是否过期快照/选错 sheet/选错月份）后再继续，不要静默跑完。
5. 检查脚本末尾的两条校验（G 列合计 = 供应商货款、四列扣款 = 扣款总额）。任何一条显示「不一致!」都必须停下排查，禁止带病交付。
6. 向用户汇报：主表数据行数、付款/扣款总额、匹配率（金额+条数双口径）、未匹配组数（有金额/0 元噪声分开）、财务空行数、大额无售后笔数，并提示需要人工确认的事项（未匹配清单含「最接近付款组/相似度」列、已回款记录、财务列待补）。
7. 用 present 交付 xlsx。

## 硬性规则（不可违背）

- **只取「供应商货款」**，审批结果「审批通过」与「转账，未通过钉钉」都算实际付款
- **刷单款判定**：费用类型=破零自刷款，或（产品=多产品 且 店铺=多店铺 且 群=多群 且 收款人属于运营人员，不限本人）→ 从货款剔除，进「破零自刷款」页，误填成供应商货款的标黄注明
- **匹配优先级**（详见 `references/matching-rules.md`）：运营字段优先于群名精确；宁可同运营近似，不跨运营精确；全部不中 → 进「未匹配清单」，**禁止强行挂账或静默调平**
- **主表一行 = 一个「运营+对接群+收款人」组合**，多笔付款合并，产品名「、」连接
- **汇款比例** = 四列扣款 ÷ 报销金额，无售后的行留空不填 0
- 财务列缺失就留空并在「运营-财务映射」标黄待补，**禁止编造**
- 标「已回款」的扣款仍计入四列，但在核对总览单列金额提示用户确认

## 常见坑（处理方式已固化进脚本，修改脚本前必读）

见 `references/matching-rules.md`：运营字段两边不一致、群名噪声、代发大账号售后按工厂名登记、跨月累计抵扣致汇款比例>100% 等。
