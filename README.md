# my-skill

这是一个用于维护个人专属 Skill 的仓库。

Skill 可以理解为一组可复用的工作说明、脚本、模板和参考资料，用来帮助 Codex 或其他 AI 助手在特定任务中更稳定、更高效地执行工作。这个仓库会集中管理我自己的专属 Skill，让常用流程沉淀下来，也方便后续持续迭代。

## 仓库定位

这个仓库主要用于：

- 维护个人常用的自动化工作流
- 编写面向特定场景的 Skill 说明文档
- 保存可复用的脚本、模板和配置
- 记录每个 Skill 的使用方式、适用场景和注意事项
- 持续优化 AI 助手处理个人任务时的上下文和操作规范

## 适合沉淀的内容

可以放进这个仓库的内容包括：

- 日常办公自动化流程
- 数据处理、表格整理、文档生成相关 Skill
- 特定网站或平台的操作流程
- 项目初始化、代码审查、发布检查等开发工作流
- 个人偏好的输出格式、命名规范和任务约定
- 常用提示词、检查清单和模板文件

## 推荐目录结构

```text
my-skill/
├── README.md
├── skills/
│   └── example-skill/
│       ├── SKILL.md
│       ├── scripts/
│       ├── templates/
│       └── references/
└── docs/
```

目录说明：

- `skills/`：存放具体 Skill，每个 Skill 单独一个目录
- `SKILL.md`：Skill 的核心说明文件，描述触发场景、执行步骤和注意事项
- `scripts/`：存放该 Skill 需要复用的脚本
- `templates/`：存放文档、表格、配置等模板
- `references/`：存放参考资料、示例输入输出或补充说明
- `docs/`：存放仓库级别的说明文档

## Skill 编写原则

编写 Skill 时，尽量遵循以下原则：

- 场景明确：说明什么时候应该使用这个 Skill
- 步骤清晰：把关键流程拆成可执行的步骤
- 输入输出明确：描述需要什么材料，以及最终应该产出什么
- 可复用：把重复操作整理成脚本或模板
- 易维护：避免过度复杂，优先使用稳定、直观的实现方式
- 可验证：尽量说明如何检查结果是否正确

## 维护流程

建议按照下面的方式维护：

1. 发现重复任务或稳定流程
2. 新建一个 Skill 目录
3. 编写 `SKILL.md`
4. 补充脚本、模板和示例
5. 实际使用后继续调整说明和流程
6. 提交到 GitHub，保留变更记录
