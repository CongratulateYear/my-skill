# my-skill

这是一个用于维护个人专属 Skill 的仓库。

Skill 可以理解为一组可复用的工作说明、脚本、模板和参考资料，用来帮助 Codex 或其他 AI 助手在特定任务中更稳定、更高效地执行工作。这个仓库会集中管理我自己的专属 Skill，让常用流程沉淀下来，也方便后续持续迭代。

## 仓库定位

这个仓库主要用于：

- 维护个人常用的自动化工作流
- 编写面向特定场景的 Skill 说明文档
- 保存可复用的脚本、模板和配置
- 记录每个 Skill 的使用方式、适用场景和注意事项
- 持续优化 AI 助手处理个人任务时的上下文和操作规范

## 适合沉淀的内容

可以放进这个仓库的内容包括：

- 日常办公自动化流程
- 数据处理、表格整理、文档生成相关 Skill
- 特定网站或平台的操作流程
- 项目初始化、代码审查、发布检查等开发工作流
- 个人偏好的输出格式、命名规范和任务约定
- 常用提示词、检查清单和模板文件

## 淘工厂工作流：安装与使用

### 依赖与运行环境

完整盘算需将以下五个目录安装到同一技能根目录：

- [淘工厂资产盘算](skills/淘工厂资产盘算/SKILL.md)：总编排。
- [淘工厂登录](skills/淘工厂登录/SKILL.md)、[淘工厂导出](skills/淘工厂导出/SKILL.md)、[淘工厂合并](skills/淘工厂合并/SKILL.md)：三个基础依赖。
- [淘工厂聚水潭](skills/淘工厂聚水潭/SKILL.md)：条件依赖，仅本次罚款成功发布且存在有效订单号时调用；安装时应一并配齐。

使用 Python 3.11+，需要 `openpyxl`、`cryptography`。源码支持 Windows/macOS；浏览器交互依赖 magpie-browser 和用户当前已打开的浏览器。优先复用登录态，失效才登录；验证码由用户处理。Windows 实机与每次新版真实API仍需单独验证，离线测试通过不等于所有线上环境已验证。

### 输入与执行

用户提供公司名称、支付日期区间、结算日期区间；仅在登录失效/切换账号时需要账号密码。公司名是淘工厂默认身份判据，ERP绑定手机号不是实际登录手机号；共享ERP公司与店铺可以不同，不自动将店铺简称作为ERP公司约束。

```bash
# 在仓库根目录运行；替换公司名和日期，安装后改成实际技能路径
python3 skills/淘工厂资产盘算/scripts/pansuan_pipeline.py --company-name "示例公司" --order-pay-start 2026-09-01 --order-pay-end 2026-09-30 --write-off-start 2026-09-01 --write-off-end 2026-10-31
```

- `--mode export`：只导出及适用的ERP回填，不生成合并主表。
- `--mode export --module 罚款`：只导罚款并执行适用的ERP回填。
- `--batch-folder "批次目录"`：多公司共用一次确定的批次目录，逐家串行执行。
- `--resume`：同公司、日期、模式和输出位置续跑；导出完成后ERP失败，不重导已完成账单。
- `--dry-run`：只显示计划，不登录、不联网导出、不写文件。
- `--erp-transport`、`--erp-browser`、`--erp-bridge-url`：独立配置ERP会话；ERP桥8901与淘工厂桥8899分离。仅用户明确指定ERP公司时使用 `--erp-expect-company`。

### 输出与匹配规则

单公司导出目录与合并主表并列；多家公司直接在同一批次目录内各放一对产物，不再套一层公司包装目录：

```text
批次目录/
  公司A_2026-09-01_2026-10-31/
    处罚数据.xlsx
    …其他账单明细
    聚水潭订单/
      公司A_聚水潭订单.xlsx
  公司A_2026-09-01_2026-10-31.xlsx
  公司B_2026-09-01_2026-10-31/
    …
  公司B_2026-09-01_2026-10-31.xlsx
```

- 仅本次罚款成功发布且存在有效订单号才调用ERP；零数据、跳过罚款、其他模块、纯本地合并、dry-run不触发。
- ERP原始线上订单号 → 罚款主订单编号；商品名称 → 商品标题；店铺款式编码 → 商品id。唯一、有效且无歧义时两项以ERP为准覆盖原值；缺单、歧义、无效字段保留原值并分类报告。
- 直接回填原处罚数据，不新增匹配副本或报告Sheet，保留原11列、行序、金额和格式。备份位于合并输入目录外，ERP原始导出位于独立子目录。
- ERP日志数量可能是商品行数，不要求等于订单数；以新增任务编号、有效类型及创建时间窗关联，多候选停止。下载后必须核验订单集合。
- full模式回填后只进行一次严格合并，再校验公司汇总30列表头、公司/总计、错误单元格、处罚明细一致性及回填不变量。公式缓存需Excel/WPS打开重算；部分缺单必须明确报告，不能称全部匹配成功。

### 安全续跑边界

公司级日志与发布凭证只保存业务标识、阶段、本地路径和摘要，不含密码、Cookie、认证头或签名下载URL。输入清单、哈希或身份变化会阻断；历史目录不自动迁移，新版工作流请使用新批次。

- ERP完成凭证已发布、公司阶段尚未记录的中断，可以核验恢复。
- 若罚款已替换但ERP完成凭证尚未写入即被强制结束，安全停止；需核实外部备份并恢复原罚款后续跑，不猜测商品改动来源。
- 淘工厂模块在远端任务创建后、模块完成状态记录前中断，原下载内核仍可能重建该未完成模块任务，需先核实远端任务；不承诺任意中断点零重复。
- OS锁防止同目录并发，匹配进程退出会释放锁；原子替换不等于断电或文件系统损坏事务保障。

## 推荐目录结构

```text
my-skill/
├── README.md
├── skills/
│   └── example-skill/
│       ├── SKILL.md
│       ├── scripts/
│       ├── templates/
│       └── references/
└── docs/
```

目录说明：

- `skills/`：存放具体 Skill，每个 Skill 单独一个目录
- `SKILL.md`：Skill 的核心说明文件，描述触发场景、执行步骤和注意事项
- `scripts/`：存放该 Skill 需要复用的脚本
- `templates/`：存放文档、表格、配置等模板
- `references/`：存放参考资料、示例输入输出或补充说明
- `docs/`：存放仓库级别的说明文档

## Skill 编写原则

编写 Skill 时，尽量遵循以下原则：

- 场景明确：说明什么时候应该使用这个 Skill
- 步骤清晰：把关键流程拆成可执行的步骤
- 输入输出明确：描述需要什么材料，以及最终应该产出什么
- 可复用：把重复操作整理成脚本或模板
- 易维护：避免过度复杂，优先使用稳定、直观的实现方式
- 可验证：尽量说明如何检查结果是否正确

## 维护流程

建议按照下面的方式维护：

1. 发现重复任务或稳定流程
2. 新建一个 Skill 目录
3. 编写 `SKILL.md`
4. 补充脚本、模板和示例
5. 实际使用后继续调整说明和流程
6. 提交到 GitHub，保留变更记录
